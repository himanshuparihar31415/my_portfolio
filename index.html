03 — THINKING

Key Product Decisions

How I think through tradeoffs — from IntelliQA

Tradeoff 01

RAG vs Fine-Tuning for Test Case Generation

RAG (KaaS)vsFine-Tuning

Fine-tuning locks in a static codebase snapshot. Enterprise QA environments change weekly. RAG with a live knowledge index allows IntelliQA to stay current without retraining cycles, reducing time-to-relevance from weeks to hours.

Tradeoff 02

Playwright MCP vs Selenium for Script Execution

Playwright MCPvsSelenium

Selenium has a large legacy footprint but poor agent compatibility. Playwright's MCP integration enables native tool-use by LLM agents — closing the loop between test generation and autonomous execution without manual handoff.

Tradeoff 03

Multi-Tenant Portal vs Client-Specific Deployments

Tenancy PortalvsCustom Deploys

Per-client deployments create unmanageable maintenance overhead at scale. A multi-tenant portal with client-specific RAG configurations delivers customization without compounding operational cost.

Tradeoff 04

No-Code Admin vs Developer-First Config

No-Code AdminvsDev Config

The primary buyers — QA managers and engineering directors — cannot own systems requiring engineering involvement for every config change. No-code admin shifts ownership to the right stakeholder.

Tradeoff 05

AWS Bedrock Single-Tenant vs Shared LLM Endpoint

Single-Tenant BedrockvsShared Endpoint

Enterprise clients require data isolation guarantees. Single-tenant Bedrock deployment via Citrix VDI ensures no data leaves the client environment — making security a feature, not a constraint.

Tradeoff 06

Modular Settings Architecture vs Flat Config

Hierarchical ModularvsFlat Config

Flat config degrades as platforms scale across clients. A hierarchical settings model — org to project to module level — allows platform-wide defaults with granular override capability.
